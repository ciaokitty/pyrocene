# Six map styles, and what actually made one readable

The map is the teaching tool. Everything else in stage 2 is bookkeeping. So an
overnight run went into building six complete styles side by side rather than
iterating on one, and a gallery page to compare them.

The six: **drawn** (hand-drawn cartographic look, now the default), **poster**
(flat editorial), **signal** (dark, high-contrast), **heat** (risk as a
continuous field), **terrain** (shaded relief) and **iso** (2.5D). All six take
the same `Scene` object and return SVG, so styles cannot disagree about facts.

## What made the difference

Not the rendering. **Dissolving the grid.** The board is 264 square cells, and
drawing them as squares made the map read as a spreadsheet. Tracing region
outlines with marching squares, then smoothing with Chaikin corner-cutting, and
adding position-keyed value noise to the coastlines turned the same data into
patches of forest. Same information, completely different comprehension. The
noise is keyed off cell position rather than a random seed, so the same board
always draws the same edge and a replay does not shimmer.

**Annotation was the real gap, not style.** Once the shapes read as land, the
question became "why did this happen", and no amount of rendering answers that.
Leader lines, labelled clusters and a health bar did. The styles that looked
best in isolation were not the ones that survived a caption.

## How they were judged

Not on live game boards. The first real "blocked" frame from an actual game was
a two-square fire enclosed on three sides by its own trench, which tells you
nothing about whether the style communicates blocking. So four scenes were
hand-built to be legible tests: a showcase board, a blocked fire, an opening
position, a focus transition. Every style renders all four, and the gallery page
puts them side by side.

This is a limit, and it should be said plainly: these were judged by one person
looking at a screen, not by a room looking at a projector from ten metres. The
ordering may not survive that.
