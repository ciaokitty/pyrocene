# Stage 2: mirroring a room onto a map, and staying away from the live game

Stage 2 is the in-person game. People sit in a room and play Mafia with
ecological roles: lantana instead of mafia, ranger instead of angel, ecologist
instead of sheriff, native trees instead of villagers. A laptop runs a small
server, the game master drives it from a phone, players join from their phones
to see their own role, and a projector shows a forest map that changes as the
room plays.

Everything is in `stage2/`. Nothing outside it moved.

## The constraint that shaped the design

The single-player game is already live and being shown to people. The
requirement was that pushing this work must not change it, and must not even
trigger a Netlify rebuild. That is a strong claim, so it is enforced rather than
promised:

- `stage2/engine/` is a frozen copy of the game engine, taken once. Stage 2
  imports from its own copy.
- A test parses every file under `stage2/` with the `ast` module and fails if
  any of them imports the live `engine`, `terminal`, `game` or `web` packages.
  Reading imports out of the syntax tree catches them wherever they sit, which
  a grep for `import` at the top of the file would not.
- `netlify.toml` gets a `[context.branch-deploy]` block whose build command does
  nothing, so branch pushes cost a no-op.
- `git diff --stat main -- engine terminal web game` must come back empty.

The copy costs us the usual thing: a fix in the live engine does not reach stage
2 until somebody re-copies it. That is the trade we wanted. Stage 2 is a
different game that happens to share physics, and it should be allowed to drift.

## Shape of the thing

A single-file `ThreadingHTTPServer`, no framework, no database. Phones get HTML
over the LAN and updates over server-sent events. SSE rather than WebSockets
because a projector and a set of phones only ever need the server to talk to
them, and SSE reconnects on its own when a phone sleeps.

The board is 264 cells over a fixed terrain with a river running through it and
a village on one side. Each player owns a patch. Lantana surviving a night grows
its patch outward. Removing a lantana player turns their patch back to native
forest; losing a native player turns theirs invasive.

## Testing it without a room

The whole thing is driven by HTTP, so a test can play a full game by posting to
the same endpoints a phone would. There are 39 tests: 23 end-to-end journeys
through complete games, 8 covering the two stages, 4 on map styles, 4 on the
isolation guard. Separately there is a headless browser pass, because the
pedagogy here is entirely visual and an API that returns the right JSON while
the projector shows nothing is worth very little. That combination caught
several of the bugs in the next entry, and it was the wrong thing to skip.
